# fsociety

An [Omarchy](https://omarchy.org) theme. Cold blue-black grade, desaturated
support colors, one signature red spent only where it means something:
focus, selection, the cursor, errors, alerts. Never decoration.

![fsociety](preview.png)

## Install

```bash
omarchy theme install https://github.com/prjoni99/omarchy-fsociety-theme.git
```

That gives you the palette, the shell styling and the wallpapers. After that
it's in the theme picker like any other: `omarchy theme set fsociety`, or pick
it from the menu.

### The full HUD (opt-in)

The HUD motion and frame (`hyprland.lua`), the red terminal cursor and the
Neovim overrides (`neovim.lua`) are code that Hyprland, your terminal and your
editor run, so Omarchy won't load them from a theme installed with
`omarchy theme install`. That's a deliberate safety rule. If you
want them, read `hyprland.lua` first, then opt in one of two ways.

**Use a working copy (recommended).** Omarchy trusts a theme folder that is a
symlink to your own checkout, and loads everything in it:

```bash
rm -rf ~/.config/omarchy/themes/fsociety   # only if you installed it above
git clone https://github.com/prjoni99/omarchy-fsociety-theme.git ~/src/omarchy-fsociety-theme
ln -s ~/src/omarchy-fsociety-theme ~/.config/omarchy/themes/fsociety
omarchy theme set fsociety
```

**Or include it from your own config.** Keep the normal install and add this to
the end of `~/.config/hypr/looknfeel.lua`. It runs the HUD only while fsociety
is active. This also covers you if your `looknfeel.lua` sets its own
animations or borders, since it loads after the theme and would otherwise win:

```lua
-- fsociety HUD: run the theme's hyprland.lua while fsociety is active.
do
  local home = os.getenv("HOME")
  local f = io.open(home .. "/.local/state/omarchy/current/theme.name", "r")
  local name = f and f:read("*l") or ""
  if f then f:close() end
  if name == "fsociety" then
    dofile(home .. "/.config/omarchy/themes/fsociety/hyprland.lua")
  end
end
```

This path covers the window HUD only. The terminal cursor and `neovim.lua`
need the working copy.

## What's in it

| | |
|---|---|
| `colors.toml` | Palette. Omarchy regenerates VS Code and the rest from this. |
| `shell.*.toml` | Eleven files theming the Omarchy shell — bar, launcher, menu, lock screen, notifications, polkit, popups, tooltips, controls, image picker, spacing. |
| `btop.theme` | Neutral greys; red only at the hot end of temperature, low memory, and the selected process. |
| `chromium.theme`, `keyboard.rgb` | Browser frame in the bar's near-black; a muted keyboard glow. |
| `backgrounds/` | Eight wallpapers: five AI-generated photos and three generated HUD frames (`art/render.py`), each in 4K and QHD. |
| `unlock.png` | Lock screen graphic, generated by `art/render.py`. |
| `icons.theme` | Yaru-red-dark. |
| `hyprland.lua` | The HUD: lock-on bracket borders, dark glass, focus glow, and motion. **Opt-in**, see Install. |
| `ghostty.conf`, `alacritty.toml`, `kitty.conf`, `foot.ini` | Terminal colors with the cursor in the accent red, generated by `regen-terminals`. **Opt-in.** |
| `neovim.lua` | Red cursor line number, errors and current search match on Omarchy's default colorscheme. **Opt-in.** |
| `regen-terminals`, `art/render.py` | Rebuild the terminal files and the art from `colors.toml`. |
| `tests/` | `check-live.sh` reads the live session back; `test-regen-terminals.sh` checks the generator. |

The design rule, if you want to extend it: the red is a signal, not decoration.
It marks keyboard focus, the active border, selection, the terminal cursor, and errors — nothing else.
Idle and hover states stay neutral so the red keeps its meaning.

## Motion & frame

The focused window wears lock-on brackets: a red border lit only at two
opposite corners. When focus moves, the brackets rotate into place once and
stop. Windows arrive fast and stop hard, with no bounce anywhere. Unfocused
windows dim, and the focused one gives off a faint red glow.

The shell uses the same brackets on its cards, and notifications and selected
rows get a red rail on the left.

The window frame and motion are part of the opt-in HUD. See
[The full HUD](#the-full-hud-opt-in) above.

## Editing the palette

The terminal files and the HUD art are generated, not hand-written. After
changing `colors.toml`, run `./regen-terminals` and `./art/render.py` so they
follow, then `tests/test-regen-terminals.sh`.

## Backgrounds

Wallpapers 1–5 are AI-generated for this theme; 6–8 are drawn by
`art/render.py`: near-black, a faint grid, one small HUD element low in a
corner. All are covered by the license below. Swap in your own by dropping files into
`~/.config/omarchy/backgrounds/fsociety/` — Omarchy picks them up alongside
the bundled ones, no need to edit the theme.
